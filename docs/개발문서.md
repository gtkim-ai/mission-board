# 가족 미션 보드 — 개발 문서

이 앱은 **Next.js가 아닙니다.**  
프레임워크·번들러·Node 서버 없이, 브라우저에서 돌아가는 **정적 HTML + Vanilla JavaScript** 이고, 백엔드는 **Supabase**(Auth · PostgreSQL · RLS · Realtime)만 씁니다. 배포는 **GitHub Pages**입니다.

| 구분 | 사용 | 사용하지 않음 |
|---|---|---|
| 프론트엔드 | HTML, CSS, Vanilla JS, PWA(`manifest.webmanifest`) | Next.js, React(앱 코드), Vue, TypeScript, npm 빌드 |
| 백엔드 | Supabase Auth / Postgres / RLS / Realtime | Express, Nest, 자체 API 서버 |
| 배포 | GitHub Pages 정적 호스팅 | Vercel 앱 라우트, SSR, API Routes |

`dashboard-ref/` 안에 React vendor가 있지만 **참고용 목업**입니다. 실제 화면은 `index.html`, `dashboard.html`입니다.

## 4. 백엔드 (Supabase)

자체 REST API를 작성하지 않습니다. 브라우저가 `mission_weeks`를 직접 읽고 씁니다. 권한은 **Row Level Security (RLS)** 가 막습니다.

초기화: Supabase Dashboard → SQL Editor → `supabase-setup.sql` 실행.

### 4.1 테이블

**`allowed_users`**

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `email` | text PK | 로그인 이메일 |
| `note` | text | 아빠 / 엄마 등 |
| `created_at` | timestamptz | |

정책: 로그인한 사람은 **자기 이메일 행만** SELECT 가능.

**`mission_weeks`**

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `week_start` | date PK | 그 주 월요일, 또는 아래 센티널 날짜 |
| `data` | jsonb | 화면별 JSON |
| `updated_at` | timestamptz | |
| `updated_by` | text | 마지막 저장 이메일 |

정책: `is_allowed()` 가 참인 인증 사용자만 SELECT / INSERT / UPDATE.

```sql
create or replace function public.is_allowed()
returns boolean
language sql stable security definer
set search_path = public
as $$
  select exists (
    select 1 from public.allowed_users
    where email = auth.jwt() ->> 'email'
  );
$$;
```

Realtime: `replica identity full`, publication에 `mission_weeks` 추가. 숙제 보드는 `postgres_changes`를 구독합니다.

### 4.2 인증 흐름

1. `signInWithPassword` / `signUp`
2. `onAuthStateChange` → `allowed_users` 에서 자기 이메일 조회
3. 행이 있으면 `allowed = true`, 게이트 닫고 `pull()`
4. 없으면 “아직 승인되지 않았습니다”
5. `잠그기` = `signOut()`

새 사용자를 쓰려면 Auth에 계정을 만든 뒤 `allowed_users`에 이메일을 넣습니다. 앱 UI에서는 승인 목록을 고칠 수 없습니다.

권장: Authentication → Providers → Email 에서 Confirm email 을 끕니다 (가족 2인).

### 4.3 클라이언트가 하는 쿼리

별도 Edge Function 없음.

```js
sb.from("mission_weeks").select("data").eq("week_start", weekKey()).maybeSingle()
sb.from("mission_weeks").upsert({
  week_start, data, updated_at, updated_by
}, { onConflict: "week_start" })
```

숙제 주간 저장은 **3-way merge** 후 upsert 합니다. 일정·병원 등 센티널 데이터는 해당 JSON을 통째로 upsert 합니다.

## 5. 데이터 모델

한 테이블에 종류를 나눠 넣습니다. `week_start`가 실제 월요일이면 그 주 체크이고, 1970년대 고정 날짜면 마스터입니다.

| `week_start` | 상수 | `data` 내용 |
|---|---|---|
| 실제 월요일 | `weekKey()` | 아이별 숙제/생활 + `_game` |
| `1970-01-01` | `SCHEDULE_WEEK` | 반복 일정 |
| `1970-01-02` | `HOSPITAL_WEEK` | 병원 · 예방접종 |
| `1970-01-03` | `MEDICINE_WEEK` | 약 |
| `1970-01-04` | `PACKING_WEEK` | 준비물 |
| `1970-01-05` | `GROWTH_WEEK` | 성장 프로필 · 측정 |
| `1970-01-06` | `RULE_WEEK` | 게임 시간 규칙 |

### 5.1 주간 체크 (`data`)

```jsonc
{
  "hajoo": {
    "2026-09-14": {
      "t": { "qt": true, "ma_calc": false, "en_r1": true },
      "h": { "hb_room": "ok", "hb_cloth": "no" }
    },
    "_meta": { "used": 30 }
  },
  "hayoo": { },
  "haseo": { },
  "_game": {
    "confirmed": true,
    "confirmedAt": "2026-09-20T12:00:00.000Z",
    "minutes": { "hajoo": 60, "hayoo": 90, "haseo": 120 }
  }
}
```

- `t`: 숙제 id → boolean
- `h`: 생활 미션 id → `""` | `"ok"` | `"no"`
- `_meta.used`: 그 주 사용한 게임 분 (숙제 보드 주말 버튼)
- `_game`: 일요일 21시 이후 확정 스냅샷. 주차마다 따로 저장되어 다음 주에 덮이지 않음

`mergeThree`는 아이 날짜 셀을 3-way로 합치고, `_game`은 `GameTime.mergeGameLock`으로 합칩니다.

### 5.2 숙제 항목 id

| id | 아이 | 주기 |
|---|---|---|
| `qt` | 공통 | 매일 |
| `en_focus` `en_word` `en_work` | 하주·하유 | 매일 |
| `en_r1`–`en_r4` | 하주·하유 | 낭독영상 하위 |
| `en_quiz` | 하주·하유 | 주 2 |
| `en_class` | 하주 | 주 3 |
| `ma_calc` `ma_class` | 하주·하유 | 매일 |
| `hr_day` | 하주·하유 | 매일 |
| `hr_week` | 하주·하유 | 주말만 |
| `sc_diary` | 하유 | 주 2 |
| `sc_read` | 하유 | 매일 |
| `sc_log` | 하유 | 주 1 |
| `dc_go` `dc_bag` `dc_sleep` | 하서 | 평일만 |
| `hb_room` `hb_cloth` `hb_change` `hb_living` | 공통 | 생활 미션 |

필수 완료(`requiredIds`)에는 **매일 항목만** 들어갑니다. `weekly` 항목은 주간 목표로만 셉니다.

### 5.3 센티널 JSON

**일정** `{ hajoo: Event[], hayoo: Event[], haseo: Event[] }`

```jsonc
{ "id": "hajoo-tkd", "kind": "academy", "title": "태권도", "place": "", "start": "16:00", "end": "17:30", "days": [1, 3] }
```

`days`: 0=월 … 6=일. `kind`: `school` | `academy` | `daycare` | `other`

**병원** `{ items: Hosp[] }` 또는 배열

```jsonc
{ "id": "h…", "kidId": "haseo", "kind": "clinic", "date": "2026-09-22", "time": "14:00", "title": "", "place": "", "note": "" }
```

`kind`: `clinic` | `vaccine`

**약** `{ items: Med[] }`

```jsonc
{ "id": "m…", "kidId": "haseo", "title": "항생제", "doses": ["am", "pm"], "start": "2026-09-18", "end": "2026-09-22", "taken": { "2026-09-19": { "am": true } } }
```

**준비물** `{ items: Pack[] }`

```jsonc
{ "id": "p…", "kidId": "hajoo", "date": "2026-09-20", "title": "체육복", "done": false }
```

**성장**

```jsonc
{
  "profiles": { "hajoo": { "birth": "2017-03-01", "sex": "F" } },
  "items": [{ "id": "g…", "kidId": "hajoo", "date": "2026-09-01", "height": 130.2, "weight": 27.1 }]
}
```

백분위: `growth-lms.js` 의 LMS → z → 백분위. 공식 계산기 [질병관리청 성장상태 측정](https://knhanes.kdca.go.kr/knhanes/grtcht/clclt/measClclt.do) 과 같은 2017 도표입니다.

## 6. 게임 시간 (`game-time.js`)

생활 미션 X 횟수로 깎지 않습니다. **핵심 숙제를 주중에 남긴 개수**로 깎습니다 (규칙 A).

```
분 = max(min_minutes, base_minutes − 남은핵심개수 × deduct_per_item)
```

기본: 120 − N×30, 최소 0. 칸 수 = `base_minutes / deduct_per_item` (기본 4칸).

기본 핵심 항목:

| 아이 | `deduct_target` |
|---|---|
| 하주 | `qt`, `ma_calc`, `en_focus`, `hr_day` |
| 하유 | `qt`, `ma_calc`, `sc_read`, `hr_day` |
| 하서 | `qt`, `dc_go`, `dc_bag`, `dc_sleep` |

- 평일(월–금)에 적용되는 핵심 항목만 센다
- `weekendOnly` 항목은 토·일에만
- 대상 id가 아이 그룹에 없으면 상태 **`unregistered`** → `미등록` 표시. `0분`/`0%`를 쓰지 않음
- 일요일 `confirm_hour`(기본 21시) 이후 `_game`에 분을 고정. 그 다음 체크는 숙제 기록만 바뀌고 분은 유지
- 규칙 JSON은 `1970-01-06`에 저장. 가족 홈 **더보기 → 규칙 설정**에서 수정

공개 API (`window.GameTime` / `require("./game-time.js")`):

| 함수 | 용도 |
|---|---|
| `defaultRules` / `normalizeRules` | 기본값 · 보정 |
| `compute(kid, data, weekStart, rules, now)` | 상태, 남은 개수, 분, 식, 칸 |
| `leftoverInstances` | 체크할 남은 목록 |
| `toggleLeftover` | 상세에서 체크/해제 |
| `freezeAll` | 주 확정 스냅샷 |
| `isConfirmedTime` | 일요일 밤 지났는지 |
| `mergeGameLock` | 확정값 3-way merge |

숙제 보드의 “30분 사용”은 `_meta.used`를 바꾸고, 화면에 `부여분 − 사용분`을 보여 줍니다.

## 7. 동기화와 충돌

부모 두 명이 동시에 체크할 수 있습니다.

1. 로컬 `data`와 `baseData`(마지막 서버 스냅샷)를 기억
2. 저장 시 서버 최신 `remote`를 다시 읽음
3. 각 칸: 로컬이 base와 다르면 로컬, 아니면 remote (`mergeDay` / `mergeKid`)
4. upsert
5. Realtime 이벤트가 오면, 내가 저장 중(`pending`)이 아닐 때만 화면을 덮음

오프라인이면 `localStorage`에만 남고 상태 문구는 “이 기기에만 저장됨”입니다.

가족 홈의 아이 상세 체크도 같은 `data`를 씁니다. 빈 주를 서버에서 받기 **전에** 일요일 확정을 하지 않습니다 (`weekLoaded`).
